# 标量动作排序可学性协议 v1

本文件与 `episodes.csv`、`split_manifest.json`、`candidates.json` 一同提交后生效；仅生成本地文件不算提交确认。阶段 0 报告已提交为 `193231e8b10dbfdfbc5bdaa0b776c79728b84312`。拟合前记录本协议远程提交号，未确认则不拟合。下面各项均在任何候选模型成绩出现前确定。

## 0. 主张与不可声称

研究问题：固定 KDA T24 s443 的真实母体续行表中，三个预声明的小型标量预测器，能否仅用决策时可得的候选信息降低 20 人组单步 regret？这是离线必要条件测试。不可声称闭环改进、跨权重泛化、训练 seed 稳定性、机制新颖性或整个动作排序方向不可能。失败只限定本数据、三种配置、预算与标量信息。模型拟合属于 B 类证据，不能借用母体冻结查表 A 类的确定性口吻。

两个竞争解释：可观测标量包含母体未利用的排序信息；或事后空间主要需要标量中缺失的信息/更强表征。最低成本的区分是按 episode/case 留出的预注册 Ridge 与非线性模型及标签打乱对照。负结果仍不能排除未试表示。

## 2. 数据划分与锁定读取

`prepare_stage1_split.py` 仅从 gzip 文本提取 key/episode/cell/eligible，不 JSON 解码带未来标签的整行。拆分完全不依赖 eligible 数量或结果。按 SHA256(`dots-stage1-split-v1|20261013|` + 十进制 case) 排序 case 93000–93174，前 35 个锁定，余 140 个依序 modulo 5 分折。六格共享同一 case 分配，完整 episode 不跨折，同一 case 的各条件也不跨折。

每格锁定 35/175 回合（20%，70 状态），开发 140 回合（280 状态）；五折各 28 回合（56 状态）。总计锁定 210 回合/420 状态，开发 840 回合/1,680 状态。`episodes.csv` SHA256 `3d4092c94a6c6efbe77049382f1955c2eb44ba13ca4fb03502d5d6a24e803af3`。该划分不再更改。

历史暴露：全表曾产生仓库 target/rescue，阶段 0 又按要求做全表聚合复现。因此锁定块不是完全无历史聚合暴露的数据，但没有候选模型的锁定评价，未按结果选择划分。CV 加载器先从原始行识别 episode，拒绝/跳过锁定行，然后才解码开发行；禁止先整表 JSON 解码后过滤。用合成行测试锁定标签不可达。

开发后按第 5 节选一个候选，先提交 `SELECTED_CANDIDATE.json`（完整配置、CV 依据、协议/拆分哈希、训练状态与模型哈希、最终读取授权条件）。确认该文件远程提交后，才允许一次锁定标签读取。锁定结果一个进程一次性计算三个组、全部规定统计和对照；不再读锁定标签，不追加模型，不因锁定结果重训/改配置。失败前未满足提交条件时保持封存。

## 3. 抽样和分母

不新增、不索取、不访问 case 90000–90199 或 92000–92499。所有训练折使用其中全部训练根状态的全部安全候选，不按结局/难度筛选。每个候选样本权重 `1/n_eligible(root)`，每个训练根状态总权重为 1；fold 的预处理仅在训练折拟合。

阶段 0 标量核查有 3 个单安全候选根状态、0 个全不安全状态：`c4-k93114-s42`、`c5-k93049-s31`、`c5-k93105-s14`。regret 只纳入至少 2 个安全候选的状态，与 target 一致（全表三组为 700/700/697）；失败率主口径包括全部状态，与 rescue 一致（全表各 700）。另报至少 2 个安全候选子集的失败率作分母敏感性。单安全候选只能选该动作，不丢弃其失败记录。每个拆分/组独立列出 n_states/n_episodes/n_cases，不能拿拆分内均值假称等于全表均值。

## 4. 评分、标签和确定性

安全池严格等于 `eligible` 为真的下标并核对 `final_scores > -1e8`。基线选 `chosen`，核对其在池内且等于基线分数最大值（允许真正并列）。保留冻结部署分数，不重新拟合或修改原评分、奖励/价值系数/安全过滤。基线 top5 用冻结工具同一规则：`pool[np.argsort(-scores[pool])[:5]]`，NumPy 版本固定。排名为该全排序位置（从 0 开始），gap 为 `scores[j] - max(scores[pool])`。

C01/C02 预测绝对 `G_A`，部署选择预测回报最大者。C03 预测失败概率，在基线 top5 内最大化 `final_scores - 0.1 * p_failure`。λ=0.1、k=5 是事前工程选择，没有理论安全保证，不据效果调节。λ 增大只沿负预测失败概率方向改分，候选间概率相等则不改排序；它可能移出母体动作分布，离线母体续行不能保证闭环解释。三种候选的所有参数见冻结 JSON，不搜索超参数。

预测分数精确平局时，若基线 chosen 在并列集合中则保留；否则按基线原分数高者，再按候选下标小者。这只是决策平局规则，下标不是特征。评分函数在验证和最终推理共用同一实现。单类失败训练标签时产生训练类的常数概率，这是事前定义的边界处理，不是新增候选。

## 5. 对照臂、顺序与选择

同期对照：原基线、所有安全候选的均匀随机策略精确期望、基线 top5 内事后最大 `G_A`（仅上限，失败记录选择该最大值对应分支）。全部同状态配对；另报基线 top5 内均匀随机，以识别仅缩小候选池的影响。随机对照无需随机抽一次动作。

三候选严格 C01→C02→C03。每个候选先完成五折的打乱控制并立即执行硬闸门，通过后才训练该候选真实标签五折；不并发跨候选越过闸门。打乱控制与真实臂同数据同预算、同特征、同配置。

打乱方法：每个开发根状态，用 `SHA256('dots-stage1-shuffle-v1|20261013|' + key)` 前 16 个十六进制字符转整数初始化 NumPy default_rng，在安全候选内置换。`G_A` 与由 `branch_outcome != success` 得到的失败标签按同一置换一起重排，确保 C03 不能保留原失败标签。每折只使用训练折打乱标签拟合，在真实未打乱的验证标签上评价。元数据 key 仅生成随机流，不进模型。

硬停止的事前操作定义：任意候选打乱臂在 20 人开发集的合并 OOF 配对 regret 均值改善 `mean(R_base - R_shuffle) > 0`，无论显著与否，立即 STOP；不得先训练下一候选，不看锁定集。仍报告区间，不将正噪声点估计直接宣称已证明泄漏。不得以容差/显著性替代这个字面硬闸门。

若全部控制过闸且至少一个候选完成，选择真实 OOF 的 20 人平均 regret 最小者；精确并列时先选全状态失败率更低者，再选编号更小者。不用 5/10 人、置信区间或锁定结果二次调参。无候选完成则 STOP。最终模型只在全开发集以同配置重拟合，先保存模型哈希再提交选择文件，之后方可读取锁定集。

## 6. 裁决条件、配对区间与多重比较

主效应为 `reduction = sum(R_base - R_candidate) / sum(R_base)`，`R = max(G_A[eligible]) - G_A[selected]`，仅至少 2 个安全候选状态。每次重采样仍在同一批根状态上配对。主要区间按用户要求，对 episode 整体有放回重采样，5,000 次，取 2.5/97.5 百分位；同一 episode 的两步始终一起。固定种子 20261013；按拆分、组和聚类类型使用独立 SeedSequence（实现中记录具体整数）。分母为 0 的 bootstrap 样本剔除并报告个数；原始分母为 0 或不足以得到区间时判 INCONCLUSIVE。

共享 case 的不同条件可能相关：另做 case-block bootstrap（同一个 case 的 C/S episode 一起），5,000 次，作为依赖稳健性敏感性。它不替换用户明确的 episode-primary 判据。如果用户主判据通过但 case 区间跨 0，明确报告脆弱性，不能声称跨条件稳健。

一次锁定主判据仅比较选定候选的 20 人组：下降 ≥20%、episode-primary 95% 区间下界 >0，且全状态所选分支失败率点估计 ≤基线，则 SUPPORTED；下降点估计 <5% 则 NOT SUPPORTED；其余 INCONCLUSIVE。失败非劣要求是用户给定的零点估计容忍，不是已证明统计非劣效。同时报告失败率配对差及 95% 区间和 case 敏感性，不额外把未要求的置信界条件加入主裁决。

三组全部报告：基线/候选/随机 regret 均值、配对差与相对下降区间、失败率及配对差区间、top5 事后上限、分母。5/10 人保持性只描述相对基线的区间，不把点估计排成趋势，不宣称已获安全保持性保证。CV 三候选用于选择而非确认性主张；除描述性 95% 区间外，三候选 20 人 CV 真标签比较报 Bonferroni 98.3333% 区间。锁定集仅一个预选主比较，不把描述性组别/指标算作额外确认性发现。

尾部诊断：报告基线 regret 最大 1/3 根状态占比；并列报告去掉按基线 regret 排序最大 1/3 状态后的相对下降及区间、基线/候选 regret 中位数与差。另报告最大 1/3 case 的绝对配对增益占总绝对增益比例，避免正负抵消掩盖支配样本。所有比例/差值随对应 episode bootstrap 区间报告；无定义值标明，不补成 0。

## 7. 阶段、预算与自动停止

顺序：本协议与拆分远程提交确认→合成隔离/数值/拆分测试→开发集加载与冻结基线校验→逐候选控制与真实 OOF→选择/全开发拟合/文件提交→一次锁定评价→一页阶段报告提交。阶段 0 全表基线/随机复现记录作为冻结参照，不为开发校验再次读取锁定标签；开发内通过独立公式逐根核对 regret/失败/随机，再与既定集合一致的直接汇总核对。

任何测试失败、任何 MANIFEST/冻结资产 SHA 不匹配、基线/随机按整数严格和浮点绝对差≤1e-9 规则复算不符，立即 STOP 保存证据，不继续实验。标签打乱闸门同上。单次拟合墙钟超过 1,200 秒或拟合异常，停止该拟合，记录原因；每个候选至多一次工程 debug/相同配置重试，不更换特征/损失/参数。仍失败则弃该候选，转下一预声明候选；测试/完整性硬失败不适用 debug 继续豁免。

阶段 1 最长 6 小时，整个用户授权流程从 2026-10-13 16:38 UTC 起最长 10 小时；不为填满预算做多余试验。仅 CPU，最多 2 计算线程，不搭仿真器，不运行闭环。总候选固定 3 个；不新增候选，不更改拆分。编码任务数由协调方记录，本执行任务为第 2 个，总计不得超过 6；不另开子编码任务。
