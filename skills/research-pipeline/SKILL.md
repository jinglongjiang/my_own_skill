# research-pipeline：研究流程总调度

## 这个技能解决什么
研究浪费时间有两种相反的方式：跳步（没筛就上大规模实验，没冻结判据就看结果），和停在核查上（一轮轮审计与交接，没有新数字）。这个技能不产出研究内容，只做三件事：认清现在在哪一步、指出下一步、在这两种浪费之间找最快拿到真实数字的路。

开始前读 `references/shared/profile.md`（使用者默认设置）和 `references/shared/evidence-rules.md`（证据规则），所有阶段都遵守。工作区结构见 `references/shared/workspace.md`。

## 两条通道
流程有两条走法。默认先问：**拿到第一个真实数字最快的办法是什么？**

**原型通道（默认优先考虑）**：候选的最小原型在本地几小时内能出数字时，直接做。
```
候选卡（一张，写清作用通道和否定方式） ──► method-build 做原型 ──► result-verdict 复算
        │                                                              │
        └── 查重：research-ledger                                       ├─ 有利 → 进完整通道的 4 → 5b 做正式验证
                                                                       └─ 不利 → research-ledger 落账
```
**完整通道**：要占用一个夜班以上的算力、要作为论文证据、或要交给执行代理时走。
```
0 定靶子 ─► 1 筛文献 ─► 2 整合 ─► 3 找创新点 ─► 4 先例对照 ─► 5a 前筛 ─► 5b 冻结协议
                                                                              │
              8 记录 ◄─ 7 裁决 ◄─ 6 执行（method-build 自己做 / exec-handoff 交出去）◄┘
                 └─► 通过：paper-claims；不通过：带着更精确的困难陈述回到 3
```
两条通道不互斥：原型通道得到的数字是开发集证据，用来决定值不值得走完整通道；它不替代冻结协议下的最终裁决。

| 阶段 | 技能 | 进入条件 | 产物 | 时间预算（超了就停下来说明） |
|---|---|---|---|---|
| 0 定靶子 | `prescreen`（靶子模式） | 有可运行的基线和日志 | `TARGET.md` | 半天 |
| 1 筛文献 | `paper-scout` | 问题能用一两句话说清 | `lit/ledger.json`、`lit/screened.md` | 半天 |
| 2 整合 | `paper-synthesis` | 至少精读 5 篇近邻 | `lit/synthesis.md` | 2 小时 |
| 3 找创新点 | `idea-forge` | 有靶子，或明确标注"无靶子" | `ideas/candidates.md` | 2 小时 |
| 4 先例对照 | `prior-art-duel` | 有候选卡 | `ideas/duel-<id>.md` | 2 小时 |
| 5a 前筛 | `prescreen`（候选模式） | 有候选卡 | `prescreen/<id>.md` | 2 小时 |
| 原型 | `method-build` | 最小原型几小时内可出数字 | 代码、smoke 记录、第一批数字 | 一天 |
| 5b 冻结协议 | `protocol-freeze` | 前筛或原型结论有利 | `protocols/<id>/` | 半天 |
| 6 执行 | `method-build` 或 `exec-handoff` | 协议已冻结 | 运行产物、`handoffs/<id>.md` | 按协议 |
| 7 裁决 | `result-verdict` | 有结果 | `verdicts/<id>.md` | 2 小时 |
| 8 记录 | `research-ledger` | 任何阶段产生终态或教训 | `RECORD.md`、`directions.jsonl` | 随手 |
| 9 写作准备 | `paper-claims` | 至少一个候选通过裁决 | `claims.md` | 半天 |

## 每次被调用时怎么做
1. 找工作区。没有就运行 `python3 "$SKILL_DIR/scripts/init_workspace.py" <目录>` 创建（默认 `research/`），并告诉用户建在哪。
2. 读 `STATE.md` 和 `RECORD.md` 的方向状态表，再看用户这次带来了什么（一个问题、一份报告、一段第三方意见、一个新想法）。
3. 按下面的路由表判断阶段，说明理由，然后调用对应技能或直接给出下一步。
4. 结束前更新 `STATE.md`：当前阶段、当前候选编号、下一步动作、阻塞项、最近一次状态变化的日期、最近一个实验数字的日期。

## 路由表
| 用户带来的东西 | 去哪 |
|---|---|
| "帮我找方向 / 找创新点" | 先查 `TARGET.md`。没有 → 阶段 0（超半天未果则带标注进阶段 3）；有 → 阶段 3 |
| 一个现成想法，问值不值得做 | `directions.jsonl` 查重 → 原型几小时内可做则走原型通道；否则阶段 4 → 5a |
| "你自己实现 / 直接动手 / 做个原型" | `method-build` |
| "任务跑得怎么样了" | `method-build` 的任务检查 |
| 一批论文或一个主题，问"有什么、缺什么" | 阶段 1 → 2 |
| 执行方的报告（完成、停止、失败都算） | 先 `exec-handoff` 的回执评估判断执行是否合规，再 `result-verdict` |
| 第三方模型的分析或反驳 | `result-verdict` 的逐条核对流程 |
| "这个方向以前是不是做过" | `research-ledger` |
| 结果出来了，问能不能写 | `result-verdict` 通过后 → `paper-claims` |

## 一条硬闸，两条默认
**硬闸：协议没冻结不读最终测试块。** 判据、数据划分、对照臂在生成正式数据之前写死；保留的测试块只在全部臂冻结之后读一次。这条不因为赶时间而让步，因为它一旦破了就无法补救。

**默认一：先有靶子再生成候选。** 靶子是"余量在哪、多大、用什么量出来"的实测答案。没有它，候选只能靠闭环大实验逐个淘汰。但量靶子本身超过半天还没结果时，允许带着"无靶子"的标注先做一个原型——原型有时就是最快的测量。

**默认二：先前筛再投入大算力。** 能在几分钟内用代数或已有数据否定的，不值得花一个夜班。但前筛的成本如果已经接近直接做原型的成本，就做原型。

用户明确要求跳过某条默认时照做，在 `STATE.md` 里记一句跳过了什么、谁决定的，后续结论带上这个限制。

## 防止停在核查上
这套流程的失败方式不只是跳步，还有反过来的一种：一轮接一轮地核查、交接、等回执，没有任何新的实验数字。出现下面任一情况时，下一步改为自己动手（`method-build`），不再转一手：
- 同一个候选连续两次停在门槛、核查或交接上，期间没有产生新的实验证据。
- 某个阶段超过了上表的时间预算。
- 门槛要求的证据拿不到，而且它不影响主结论的配对比较——把它降为披露，继续往下走。
- 执行代理因为预算估算停下，而重算后发现只需改排程。
每次调用时看一眼 `STATE.md` 里"距上一个实验数字过去了多久"，超过两天就把这件事放在答复的第一句。

## 同时有多条研究线时
`STATE.md` 里每条线一个小节，各有各的候选编号前缀。回答问题前先确认用户现在说的是哪条线，引用数字时写明来源线。串线是这类项目里最常见的事实错误。

## 输出
简短。说清：现在在哪个阶段、依据是什么、下一步调用哪个技能、预计成本、有没有阻塞。不复述整个流程。
