# idea-forge：寻找创新点

## 这个技能的立场
想法不缺，缺的是能便宜地淘汰的想法。一个候选如果只能靠几千个 episode 的闭环实验才知道有没有用，那它的成本就是一到两天，十个候选就是两三周。所以这里对候选的要求不是"新"，而是：**它声称改善的那个量已经被量出来有余量，而且有一个几分钟到几小时的检查能否定它。**

先读 `references/shared/evidence-rules.md` 和 `references/shared/profile.md`。

## 入口检查
1. **靶子。** 读 `research/TARGET.md`。它要回答：余量在哪个环节、多大、用什么数据量出来的、尺子能不能看见一个已知有效的改动。没有或状态为"未测"时，先交给 `prescreen` 的靶子模式；如果量靶子超过半天仍无结果，或用户要求直接出候选，可以继续，但每张候选卡的"对应的靶子"一栏写"无实测靶子"，并优先生成能用几小时原型直接检验的候选。
   为什么默认要靶子：没有它，候选再多也只是在猜余量在哪。
2. **已杀清单读过。** 读 `research/RECORD.md` 的方向状态表和 `directions.jsonl`。已杀的方向不再提，除非能说明这次和上次死因无关。
3. **文献缺口存在。** 读 `research/lit/synthesis.md`。没有 → 先 `paper-scout` + `paper-synthesis`。用户赶时间要求跳过时可以继续，但每张候选卡的"最接近工作"一栏标"未做文献核对"。

## 生成候选的两条路

### 路一：对标改进（默认先走这条）
对 `synthesis.md` 里的主对标论文：
1. 写出它的机制链：输入 → 表示 → 打分/决策 → 训练信号。
2. 把靶子对上去：余量落在链条的哪一环？
3. 只改那一环。候选 = "在它的协议上，把第 k 环从 A 换成 B，因为实测余量在这里"。
这条路的优点是基线、协议、对比对象都是现成的，审稿人容易理解贡献在哪。

### 路二：跨领域机制迁移
1. 取靶子和缺口，写出去掉领域名词的结构描述（写法见 `paper-scout/references/query-craft.md` 的抽象阶梯）。
2. 从台账里 `mechanism-source` 角色的论文中，至少比较两个来源机制再选。
3. 过迁移自测：来源设定确实不同；借的是具体机制；能说出结构为什么相同；适配利用了这个结构。四条缺一就不是迁移。

两条路各出候选，总数控制在 3–5 个。多了筛不过来，而且后面的往往是前面的变体。

## 利用环境的结构
生成前花几分钟列出环境和代码里"免费"的东西，它们常常就是方法的支点。读 `references/free-structure.md`，里面是一份检查清单（例如：哪些量在仿真里可以精确得到而别人用近似；哪些分支可以无代价地反事实重放；训练和部署之间有哪些不对称）。

## 候选卡
每个候选一张，写入 `research/ideas/candidates.md`，模板在 `assets/candidate-card.md`。必填项及其理由：

| 项 | 为什么必须有 |
|---|---|
| 一句话机制 | 说不成一句话的通常还没想清楚 |
| 改的是哪一环、其余不变的是什么 | 决定对照实验怎么设 |
| **作用通道** | 它通过哪条计算路径改变最终决策。写到公式层面：哪一项变了，这一项是否在候选之间有差异。只给所有候选加同一个常数的改动不会改变排序 |
| **必要条件**（1–3 条） | 方法有效所必须成立的事实。每条都要可以单独被检验 |
| **最便宜的否定方式** | 针对最脆弱的那条必要条件：用什么已有数据或代数推导、多长时间、看到什么算否定 |
| 对应靶子的哪部分余量、上限多少 | 防止追一个本来就没有余量的量 |
| 最接近的已有工作与具体差别 | 交给 prior-art-duel 核对 |
| 来源（路一：对标论文与环节；路二：来源论文、借用机制、共享结构） | 可追溯 |
| 训练期/部署期各改什么 | 部署零改动的方法更容易被接受，也更容易配对评测 |
| 成本估计 | GPU 小时与墙钟，分"前筛 / 最小试验 / 完整验证"三档 |
| 主要风险与竞争解释 | 如果它有效，除了你说的机制还可能是什么（更多数据、更多训练、信息泄漏） |
| 需要的对照臂 | 至少包含一个"同数据同预算但不用你的机制"的臂 |

## 不合格的候选（直接不写进卡）
- 作用通道说不出来，或者推导后发现对所有候选动作是共模的。
- 必要条件无法单独检验，只能"跑完整实验看结果"。
- `TARGET.md` 已经测过，而且测出来这个量没有余量。（靶子还没测时不在此列：按入口检查的说明标注"无实测靶子"，走原型通道。）
- 和已杀方向死因相同。
- "把模型 X 用到任务 Y 上"而没有指出它解决哪个实测瓶颈。

## 排序与交付
按"否定成本从低到高"排，不按"看起来多有前途"排。先查便宜的。

向用户汇报：每个候选一句话机制 + 最便宜的否定方式和成本；推荐先查哪个；哪些想法因为什么没写进卡。下一步：排第一的候选如果几小时内能做出原型，直接交 `method-build`；否则做 `prior-art-duel` 和 `prescreen`。

明确说明：候选卡是提案，不是有效性证据，也不是新颖性证明。
