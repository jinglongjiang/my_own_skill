# research-ledger：研究记录

## 为什么单独做一个技能
长周期研究里，上下文会丢：换会话、压缩、隔了几天。丢了以后最常见的两个事故是把已经否定的方向重新推荐一遍，以及把一条研究线的数字安到另一条线上。记录的作用就是让这两件事查得到。它也是别的工具（评审、检索、构思）的输入，所以要写成别人不看对话也能读懂。

先读 `references/shared/evidence-rules.md`。文件位置见 `references/shared/workspace.md`。
命令里的 `$SKILL_DIR` 指本文件所在目录，运行时换成它的绝对路径；`research/` 指用户项目里的研究工作区，不在技能目录下（见 `references/shared/workspace.md`）。

## 两个载体
- `research/RECORD.md`：给人读的完整记录，结构见下。
- `research/directions.jsonl`：给机器查的方向台账，用 `scripts/ledger.py` 维护。
两者要一致：改了一个就改另一个。`directions.jsonl` 没有写锁，同一时间只让一个会话写它。

## RECORD.md 的结构
1. **实验台账**：每个实验一行——做了什么、目录、证据类别（A 冻结权重配对 / B 独立训练）、结果（带数字和【实测】等标签）、限制。
2. **方向状态**：每个方向一行——编号、名称、状态、依据、日期。状态只有四种：
   - 进行中
   - 通过（写明通过的是哪一级：前筛 / 开发集 / 最终裁决）
   - 已杀（写死因，区分"必要条件被否定"和"预算内未检出"）
   - 搁置（必须写解除条件）
3. **资产**：权重与哈希、数据集、保留的测试块及其使用历史、可复用脚本、反事实表。
4. **噪声底**：同配置跨 seed 的各指标波动（均值与最大值）。裁决时用它判断差异是否超出噪声。
5. **工程缺陷与已知陷阱**：死配置项、字段顺序、只在某个阶段生效的开关、本地缺失的依赖等，带 文件:行号。
6. **教训**：每条写成"下次在什么情况下应该怎么做"，而不是"这次哪里错了"。

多条研究线时，每条线一个文件或一个一级标题，条目带线名。

## 什么时候落账
| 事件 | 写什么 |
|---|---|
| 裁决完成 | 实验台账一行；方向状态更新；`ledger.py set` |
| 前筛淘汰 | 方向状态"已杀"+ 死因是哪条必要条件 |
| 先例对照"已被覆盖" | 方向状态"已杀"+ 覆盖它的论文 |
| 一个结论被更正 | 在原条目上标"已更正"并写新值；教训一条 |
| 发现工程陷阱 | 陷阱一条，带位置 |
| 新资产（权重、表、保留块被读取） | 资产一节；保留块的读取必须记录 |
| 得到新的噪声估计 | 噪声底一节 |

只记事实和状态。不写推测的原因；未查明的写"未查明"。

## 查重（提出任何新方向之前）
```
python3 "$SKILL_DIR/scripts/ledger.py" dup "一段描述新想法的话"
```
命中已杀方向时，必须能说出这次与上次死因无关才继续；说不出就不提。关键词比对会漏（尤其是中英文混用时），所以登记方向时中英文关键词都写，并且查重后仍要读一遍 `RECORD.md` 的方向状态表。

```
python3 "$SKILL_DIR/scripts/ledger.py" add --title "…" --keywords "中文词,english term" --axis "部署期规则"
python3 "$SKILL_DIR/scripts/ledger.py" set C07 已杀 --reason "…" --evidence 路径
python3 "$SKILL_DIR/scripts/ledger.py" axes
```
`--axis` 标明这个方向改的是哪一环（输入、表示、训练信号、部署期规则…）。`axes` 汇总后如果某条轴上连续已杀多个且无一通过，说明该停下来问余量是否在这条轴上，而不是继续换候选。

## 问题陈述（给别的工具或别人用）
用户要一份自包含的陈述时，从记录里生成，结构：一句话问题；框架与接口；已有实测（带口径与来源）；做过的方向及状态；资产与约束（算力、时间、必须是方法论文）；尚未回答的问题。写完检查：不看对话的人能否读懂；有没有混进别的研究线；每个数字能否回到原始文件。

## 汇报
落账后只说改了哪几条。用户问进展时，给方向状态表加一句"当前唯一在走的是什么、卡在哪"。
