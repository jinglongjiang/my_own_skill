# prior-art-duel：先例对照

## 两种对照，都要做
- **新颖性对照**：有没有人已经做了你的核心机制。
- **性能对照的可行性**：你打算比的那个基线，在它自己的协议下你能不能公平地比。
很多"创新点"死于第一种，而很多"提升"在审稿时死于第二种：数字比对方高，但口径不同。

先读 `references/shared/evidence-rules.md`。输入是 `research/ideas/candidates.md` 里的一张候选卡。
命令里的 `$SKILL_DIR` 指本文件所在目录，运行时换成它的绝对路径；`research/` 指用户项目里的研究工作区，不在技能目录下（见 `references/shared/workspace.md`）。

## 步骤

### 1. 专门去找能杀死它的论文
用同问题检索，但检索词换成**候选的机制**而不是问题：
```
python3 "$SKILL_DIR/../paper-scout/scripts/lit.py" search "<机制关键词> <任务关键词>" --regime same
```
至少三组检索词：核心机制 + 领域；机制 + 任务；技术名 + 评测环境。再加一组去掉领域词的机制检索（机制可能在别的领域早就有了，这会改变你能声称什么）。
以审稿人的立场搜：目标是找到那篇让你撤稿的论文，不是确认没有。

### 2. 精读最接近的 3–5 篇
按 `paper-scout` 的规矩登记为 `near-miss`、full 级阅读。只看标题和摘要不能下"相同"或"不同"的结论。

### 3. 四轴判定
对每篇近邻填：

| 轴 | 它 | 我 | 是否真的不同 |
|---|---|---|---|
| 作用对象（改的是什么：输入、表示、打分、训练信号、决策规则） | | | |
| 机制（具体怎么做） | | | |
| 输入粒度/信息来源（用了什么信息，训练期还是部署期） | | | |
| 问题设定（环境假设、规模、分布） | | | |

规则：
- 标题相似不构成重复；四个轴找不出任何一个真正不同才算重复。
- 只有"问题设定"一轴不同（同样的方法换了个环境）→ 是应用，不是方法创新，按这个定位写。
- 差别如果只是换了说法（同一机制的新名字）→ 不算不同。
- 每个"不同"都要能落到对方论文的具体位置（Sec./Eq.），否则标"未核实"。

### 4. 性能对照的可行性
对打算比较的每个基线，从 `research/lit/synthesis.md` 的评测口径表取它的协议，回答：
1. 我能在它的环境、规模、训练分布上跑我的方法吗？
2. 它报的统计强度是什么（单次 / 多 seed 均值 / 配对）？我至少要做到同等，最好更强。
3. 它的数字是我复现的，还是从论文抄的？抄来的数字只能在口径完全一致时并列。
4. 我的方法用了它没有的信息或预算吗（额外标签、额外训练、特权信息）？用了就必须有一个"同信息同预算但不用我的机制"的对照臂，否则提升可以归给信息而不是方法。

### 5. 结论
三选一，写入 `research/ideas/duel-<编号>.md`（模板 `assets/duel-report.md`）：
- **可区分**：至少一个轴真实不同，写清是哪个、对方论文哪里可以印证。
- **部分重合**：核心机制已有，但有具体的增量。写清增量是什么，并把候选卡的定位改成这个增量。
- **已被覆盖**：找不到真实差别。写出是哪篇、它已经解决了什么。候选回 `idea-forge`，在 `research-ledger` 里记一笔。

无论哪种结论，都附一份**不可声称清单**：基于找到的先例，论文里不能说的话（例如"首次提出…""首次发现…"）。

## 表述的分寸
- "未检索到直接重合的工作"只说明在这些检索式下没找到。写出用了哪些检索式。
- 对照结论是元数据层面的判断（谁做了什么）。不从检索片段里引用对方的数字或方法细节，那些要来自精读笔记。
- 新颖性成立不等于方法有效，更不等于值得做——那是 `prescreen` 的事。

## 汇报
三五句话：最危险的先例是哪篇、差别在哪个轴、结论、不可声称的话、公平比较需要加哪个对照臂。
