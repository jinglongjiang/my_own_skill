# result-verdict：结果裁决

## 立场
这个技能的用户最不想要的是"事后认错"：先给一个说得通的解读，下一轮被指出站不住。所以顺序固定为：**先复算，再做能推翻自己的检查，最后才写结论。** 宁可交一条验证过的结论加一句"其余未验证"，也不交一套自洽但没验证的故事。

先读 `references/shared/evidence-rules.md`，它是这个技能的主要内容；下面是操作顺序。
命令里的 `$SKILL_DIR` 指本文件所在目录，运行时换成它的绝对路径；`research/` 指用户项目里的研究工作区，不在技能目录下（见 `references/shared/workspace.md`）。

## 一、拿到结果后

### 1. 回到原始文件
不从报告摘要里抄数字。找到逐例或逐步的原始文件，自己复算报告里的关键数字。复算不出来的数字标"未验证"。同时确认：这批结果属于哪条研究线、哪份权重、哪批 case（防串线）。

### 2. 配对统计
两臂在同一批 case 上的结局，用：
```
python3 "$SKILL_DIR/scripts/paired_stats.py" --a <基线文件...> --b <候选文件...> \
    [--ni collision:2.0] [--hold success:-1.0] [--family 3]
```
它只有一个统计目标：事件比率之差（候选 − 基线，按配对加权）。检验是以 case 为单位的精确符号翻转检验（每个 case 只出现一次时就是精确 McNemar），区间是按 case 聚类的 bootstrap，非劣效与保持性判定针对同一个差值。输入格式见脚本开头说明。
读输出时注意三点：
- 同一个 case 出现在多个文件里（例如同一批 case 跑了两个场景）时，它们不是独立样本，脚本自动以 case 为单位。
- "多少个 case 变好 / 变坏"只是描述。多数 case 小幅变好、少数 case 大幅变坏时，case 个数的方向和平均比率的方向会相反；下结论看平均差和它的 p 值。
- 事件很少或为零时 bootstrap 区间会退化成零宽，这时以保护界为准。"两臂都是 0 次碰撞"在小样本下不是安全性证据。
两臂的 case 不一致时脚本默认报错；回报列给了就必须全是有限值。
离线的单步 regret 类结果用 `prescreen/scripts/regret_ruler.py`。

### 3. 稳健性检查（写结论之前全部做完）
逐项过 `references/robustness-checklist.md`。最常翻车的六项：
1. 点估计有没有区间？区间包含零吗？
2. 均值是不是被一两个样本支配？
3. 做了几次检验，校正了吗？
4. 跨条件比较的原始量，基线本身是否也变了？
5. 没检出差异时，这次能检出多大的效应？
6. 高改动率是不是被当成了收益？
任何一项改变了读数，就按改变后的写。

### 4. 对照预注册条件
有冻结协议时，逐条对 `PROTOCOL.md` 的裁决条件，写"满足 / 不满足 / 无法判定"及对应统计量。协议写了每种结果组合对应什么结论，就用那个结论，不重新解释。没有协议时明确说"无预注册判据，以下为事后读数"，并降低结论强度。

### 5. 结论分层
| 层 | 例子 | 需要的证据 |
|---|---|---|
| 现象存在 | 分布外决策质量下降 | 区间分得开，口径一致 |
| 位置 | 余量在头部候选的次序里 | 上限分析，注明是事后上限 |
| 成因 | 是监督方式造成的 | 干预实验区分了至少两个竞争解释 |
| 可修复 | 某方法能改善 | 闭环配对、过预注册条件 |
每层单独标状态。前一层成立不自动带出后一层。问题陈述的措辞不能预设尚未确定的那一层。

### 6. 写裁决
写入 `research/verdicts/<编号>.md`（模板 `assets/verdict-template.md`）。开头是一句话结论和状态；然后是数字表、稳健性检查的结果、边界（单 seed？单骨干？样本量？）、不能由此得出的结论、下一步的方案与推荐。
零结果照零结果写：改了多少决策、净差多少、区间多宽、能排除多大的效应。然后交给 `research-ledger` 落终态。

## 二、核对第三方的分析或反驳

用户贴来另一个模型或审稿人的意见时：
1. 把对方的意见拆成逐条的事实声称和建议。
2. 每条回到原始数据或代码核对，不凭印象判断谁对。需要算就算。
3. 逐条给判定，用表格：`声称 | 判定（正确 / 部分正确 / 依据选错但结论成立 / 错误）| 证据`。
4. 对方对的地方直接承认并说明落实方式；对方引用的证据不是最强的那条时指出更强的；对方把"有指向性"写成"已确定"时指出来。
5. 涉及自己先前结论的，按证据规则第 7 条处理：作废哪条、正确的是什么、影响什么决定；同时检查同一种推理方式是否在别处重复出现。
6. 不迎合。对方说得对不等于全对，自己被指出一处错不等于其余都要让步。复核后原结论成立的，明确写"原结论成立"。

开头先回答用户真正问的那句（"对方这段话是否属实"），再展开。

## 三、关于"又是零结果"
连续多个候选净零时，先别继续换候选。问三件事：
1. 这些候选是不是都在同一条轴上（都是部署期规则、都是输入侧）？
2. 余量被量过吗？没有就去 `prescreen` 的靶子模式。
3. 有没有一个共同的解释能说明它们为什么都看不见余量？把它写成可检验的陈述。
多个一致的零结果本身是证据，但它是诊断型证据。用户的目标是方法论文时，它的用途是指向下一个候选该在哪条轴上，而不是作为主贡献。
