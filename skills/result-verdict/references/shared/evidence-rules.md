# 证据规则（全部技能共用）

这套规则存在的原因：研究里最贵的错误不是算错，而是把"能解释数据的说法"按"已验证的结论"发出去，然后别人据此投入几天算力。下面每一条都对应一次真实发生过的返工。

## 1. 三种状态，只用这三种
| 状态 | 含义 |
|---|---|
| 已验证通过 | 有本轮可复算的客观证据（命令输出、数值、文件、测试） |
| 未验证 | 做了或说了，但没有足够证据 |
| 已确认失败 | 有证据表明不满足预期 |
不写"基本没问题""应该可以"。命令发出、进程存在、文件生成、日志暂无报错，都不是成功的证据。

## 2. 四种论断标签
【实测】附本轮工具输出或原始文件路径；【代码事实】附 文件:行号；【推论】由前两者推出，写明前提；【猜测】没有支撑。
推论与实测不写在同一句里。一个数字如果是由几何或公式推出来的，它是【推论】，不是【实测】。

## 3. 两类实验证据
- **A 类**：冻结权重 + 同一批 case 配对。没有训练随机性，结论可靠到 case 抽样误差为止。
- **B 类**：需要独立训练。2 个 seed 只能发现"不复现"，不能证明"稳定"。
写结论时注明是哪一类。B 类结论不借用 A 类的确定性口吻。

## 4. 给出解释或提出实验之前
1. 机制解释至少给两个竞争解释，说明哪个实验能区分它们，哪个最便宜被证伪。只给一个不合格。
2. 提出"改某个量看变化"的实验前，写出：自变量的数学形式；它在参数空间实际移动的方向（符号是否依赖取值范围）；它相对训练分布的位置（"保留了某个边际或配对"不等于在分布内）；系统是否有结构保证让读数能按预期方向解释。
3. 对本轮最关键的结论，先执行最便宜的那个可能推翻它的检查。没做就降级为【猜测】。
4. 不为原因命名。写"原因未查明"加可能方向，不写"大概是 X 导致"。
5. "唯一解释""不可行""必然""显然"这类词出现前，先在已有材料里找一遍反例，并注明找了什么。

## 5. 统计底线
- 任何比值、差值、比例，报点估计的同时报区间（按 case 或 episode 聚类 bootstrap，不把步当独立样本）。
- 均值类统计先查尾部集中度：最大 1 例、前 3 例占总量多少。被几个样本支配时并列报告去尾和中位口径。
- 做了几次检验就按几次校正。
- 同一个 case 出现在多个条件或多个文件里时，它们不是独立样本：检验和区间都以 case 为单位。
- 判断趋势用针对趋势的检验（相邻差值的区间、有序条件的趋势检验），不靠各点区间是否重叠。
- 原始量的跨条件对比先问"基线本身变没变"。能归一化就归一化（例如相对随机基线消除了多少）。
- "没检出效应"和"证明无效应"是两件事：报出区间，说明这次能排除多大的效应。区间半宽不等于功效意义上的最小可检出效应。
- 改动率（决策改变了多少）不是收益证据。高改动、净零是常见结果。

## 6. 防串线
同时推进多条研究线时，每个数字带上它来自哪条线、哪份权重、哪批 case。引用旧结论前回到原始文件确认它属于当前讨论的对象。

## 7. 撤回
发现错误时：一句话说明哪条结论作废、正确的是什么、对当前决策有无影响。同时检查产生它的推理方式在本轮其他地方有没有再次出现。不铺陈、不反复道歉。
反过来也要防过度修正：复核后原结论成立的，明确说"原结论成立"，不要为显得谨慎而撤回正确的东西。

## 8. 汇报格式
技术问题按：现象 → 问题 → 证据/缘由 → 多个方案 → 推荐。方案不少于两个，推荐只有一个并说明理由。先给结论，再给支撑。
