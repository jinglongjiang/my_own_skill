# 稳健性检查清单

写结论之前逐项过。每项记"做了，读数不变 / 做了，读数改变（改成什么）/ 不适用"。

## 数字本身
- [ ] 关键数字由原始文件复算得到，而不是从摘要抄来。
- [ ] 口径自检：我用的"选中动作""可行集合""回报"定义和产生数据的代码一致（例如 `chosen` 是否等于打分最大者；打分里是否已含常数惩罚）。
- [ ] 数字属于当前讨论的研究线、权重、case 块。

## 不确定性
- [ ] 每个比值、差值、比例有区间；重采样按 case 或 episode 聚类。
- [ ] 尾部集中度：最大 1 例、前 3 例占总量的比例。高时并列报告去尾与中位口径。
- [ ] 多个点连成"趋势"之前，对趋势本身做检验（相邻两点的差值区间，或对有序条件的趋势检验），不靠各点区间是否重叠来判断——区间重叠既不能证明没有趋势，也不能证明有。某个点由极少数样本支配时，先说明它不可靠，再谈趋势。
- [ ] 检验次数与校正。未校正的 p 接近 0.05 时，校正后通常不显著。

## 比较是否公平
- [ ] 跨条件比较原始量时，参照基线（随机动作、任务难度）是否也变了；能归一化就归一化。
- [ ] 两边样本是否配对；不配对时差异里混有 case 抽样噪声。
- [ ] 候选对"分数带内随机改动"的比较是否做了。
- [ ] 差异是否超过同配置跨 seed 的噪声底（`RECORD.md` 的噪声底一节）。

## 解读
- [ ] 推导量和实测量分开写。
- [ ] 上限（事后最优、oracle）没有被写成可达增益。
- [ ] 改动率没有被当成收益。
- [ ] "没检出"写明了区间宽度（及能排除的效应大小），没有写成"无效"。
- [ ] 给了不少于两个竞争解释，并说明哪个检查能区分。
- [ ] 没有为原因命名；未查明的写"未查明"。
- [ ] 结论的适用范围写全：几个 seed、几个骨干、哪些场景、样本量。

## 反方向
- [ ] 有没有因为显得谨慎而撤回一个其实成立的结论？复核后成立的要写"成立"。
- [ ] 旧结论里的"例外条件"是否被忽略，导致误以为它被新数据推翻。
