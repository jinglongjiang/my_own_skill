# prescreen：高成本实验前的筛查

## 为什么需要
一个候选走完整闭环评测要一到两天。很多候选其实可以更早被否定：推一下公式发现改动对所有候选动作是同一个常数；查一下已有数据发现它选的动作并不更好。这个技能把这类检查固定成流程，并且对"检查本身有没有资格下结论"保持警惕——弱探针的失败不能当成方法的失败。

先读 `references/shared/evidence-rules.md`。
命令里的 `$SKILL_DIR` 指本文件所在目录，运行时换成它的绝对路径；`research/` 指用户项目里的研究工作区，不在技能目录下（见 `references/shared/workspace.md`）。

## 靶子模式：先量余量
在生成任何候选之前回答：基线策略离"每一步都选对"差多少？差在哪？

1. **找或造一张反事实表**：一批决策状态，每个状态下每个候选动作的真实回报。来源可以是仿真器的反事实重放（先查 `idea-forge/references/free-structure.md`，很多环境可以免费重放），也可以是已有日志。表的格式见 `references/table-format.md`。
2. **运行尺子**：
   ```
   python3 "$SKILL_DIR/scripts/regret_ruler.py" target <表文件...> --group <分组字段> --group-map "..." --cluster <episode字段>
   ```
   它给出：基线 regret、相对随机动作的消除率及区间、去尾和中位口径、最大样本占比、top-k 重排序上限、组间差。
3. **读数**（每条都写进 `research/TARGET.md`）：
   - 消除率在训练分布内和分布外差多少？区间是否分得开？这比成功率下降更干净，因为它不把"任务变难"算进去。
   - top-k 上限大 → 好动作已经在头部，问题在头部内的次序；上限小 → 好动作没进头部，问题在更上游。
   - 最大 1 例占比高 → 均值不可单独引用，报多种口径。
4. **写明尺子的资格**：样本量、单步还是多步、回报表依赖哪个续行策略、阳性对照做没做。没做阳性对照的尺子只能提示方向，不能淘汰候选。

没有反事实表、也造不出来时，靶子模式改用已有日志能支持的最强替代（例如逐例配对的失败分解），并在 `TARGET.md` 里写明替代量和真正想量的量之间差什么。

## 候选模式：三道检查，从便宜到贵
对一个候选（`research/ideas/candidates.md` 里的一张卡），按顺序做，任何一道给出"淘汰"就停。

### 第一道：作用通道（几分钟）
把决策公式逐项写出来，标明哪些项在候选之间有差异、哪些是共模。然后分两种情况：
- **改动在网络之外、以加法进入分数**（奖励系数、惩罚常数）：可以用代数判定。改动项在实际存活的候选之间没有差异 → 在价值网络固定的前提下它不改变即时排序，**部署期改动的版本可以淘汰**，不需要实验。同一个改动如果用于重新训练，会改变价值网络本身，这条推导管不到。
- **改动经过网络**（换输入、遮蔽通道、换选人、换权重）：不能用代数判定。输入上的扰动对所有候选相同，不代表分数变化相同——网络是非线性的。这时实测：
  ```
  python3 "$SKILL_DIR/scripts/regret_ruler.py" channel <基线表...> --alt <新打分文件> --key <主键字段>
  ```
  看分数变化在候选之间的离散程度相对原有间距有多大、第一名换了多少。
通道存在时估算量级，和现有打分间距比；差几个量级写明"通道存在但很窄"。
细则和例子见 `references/channel-check.md`。这一道用错的后果是误杀，所以拿不准改动走哪条路时按"经过网络"处理。

### 第二道：查表（已有数据，几秒到几分钟）
候选只改排序规则时，写成一个函数直接查反事实表：
```
python3 "$SKILL_DIR/scripts/regret_ruler.py" rule <表文件...> --rule my_rule.py:rule --group ...   # 规则函数写法见 assets/example_rule.py
```
候选改了打分（换输入、换权重）时，在同一批状态上算出新打分再比：
```
python3 "$SKILL_DIR/scripts/regret_ruler.py" compare <表文件...> --alt <新打分文件> --key cell,case,root_step --group ...
```
输出两个对比：候选对基线、候选对**分数带内随机改动**。第二个对比不能省：改了很多决策但和随机改一样好，说明规则没有选到信息。

### 第三道：最小判别测试（新数据，至多几小时）
前两道过了但证据仍不足时，设计**一个**最便宜的新测试。写清：
- 它区分哪两个解释（候选机制 vs 最强替代解释），两者各预测什么结果
- 预算、对照、停止条件
- 什么结果仍然无法判断
不设计多个，不顺手加"顺便看看"的项目。

## 测试有没有资格淘汰候选
每个"淘汰"结论必须回答下面四问，答不上来的降为"证据不足"：
1. 失败的是方法成立的**必要条件**，还是只是一个代理指标？
2. 这个测试能看见已知有效的改动吗（阳性对照）？
3. 给出的信息是不是按方法实际会用的方式使用的？（"给了真值仍无改善"可能只说明使用方式不对。）
4. 样本量下能检出的最小效应是多少？观测到的效应是在这个范围内还是范围外？

## 输出：只有三类
| 结论 | 条件 | 下一步 |
|---|---|---|
| 淘汰当前具体版本 | 某条必要条件被有资格的检查否定 | `research-ledger` 记死因；回 `idea-forge` |
| 值得进入最小试验 | 通道存在、查表有利或无法查表但无反证 | `protocol-freeze` |
| 证据不足，暂不追加大投入 | 检查不够敏感或覆盖不够 | 写明缺什么，补得起就补 |

"没证明有用"不写成"已证明无用"；也不要求先证明最终指标提高才允许做原型。淘汰的是"这个具体版本"，不是整类方法。

写入 `research/prescreen/<候选编号>.md`，模板在 `assets/prescreen-report.md`，一页以内。

## 尺子自己的验收
第一次在一个项目里用这把尺子时，先回测，方法见 `references/backtest.md`：拿一个已知失败和一个已知成功的历史候选，只给当时的材料，看尺子的读数与闭环结局是否一致。验收标准是它提出的检查可执行且足以支持停止，不是"猜中了结局"。回测结果写进 `TARGET.md` 的"尺子的资格"。
