# 作用通道检查

## 先分清改动走哪条路
代数判定只对一类改动有效，用错了会误杀候选：

| 改动的位置 | 能否用代数判定 | 怎么查 |
|---|---|---|
| 在网络**之外**、以加法进入最终分数的项（奖励系数、惩罚常数、加性偏置） | 能 | 推导 Δ(a) − Δ(b) |
| 经过网络的任何改动（换输入、遮蔽某个通道、换选人、换权重） | **不能** | 实测每个候选的分数变化 |
| 改过滤集合、候选集合本身 | 不能只看分数 | 先看集合怎么变，再看集合内的次序 |

## 做法（网络之外的加性改动）
1. 从代码里抄出决策公式，不凭记忆。例如前瞻式价值决策：
   `score(a) = r(s,a) + γ·V(g(s,a)) − λ·risk(a)`，再过滤、再取最大。
2. 每一项标三个属性：
   - 是否依赖候选 a（不依赖 → 共模，对排序无影响）
   - 在**实际存活**的候选之间是否有差异（过滤之后剩下的那些）
   - 训练期和部署期是否都生效
3. 把候选的改动写成对某一项的修改 Δ(a)。
4. 判断 Δ(a) − Δ(b) 对存活候选对 (a,b) 是否恒为零。

## 做法（经过网络的改动）：实测差分
在同一批已记录的状态上，用改动前后的网络各算一遍全部候选的分数，然后：
```
python3 "$SKILL_DIR/scripts/regret_ruler.py" channel <基线表...> --alt <新打分文件> --key <主键字段>
```
它报告每个状态里"分数变化在存活候选之间的离散程度"相对"原第一名与第二名间距"的比值，以及第一名被换掉的比例。
- 离散程度相对间距很小、第一名几乎不换 → 这次改动在这批状态上基本是共模的。这是**实测结论**，只对这批状态和这份权重成立。
- 离散程度与间距可比或更大 → 通道存在，进入查表看它换到的动作是否更好。
即使实测为共模，结论也只能写"该改动在这批状态上不改变排序"，不能写"这个输入量不重要"。

## 三种结局
- **恒为零**（仅限网络之外的加性改动，且推导覆盖了全部存活候选）→ 在**价值网络固定不变**的前提下，这个改动不改变即时排序，作为"部署期改动"的版本可以淘汰。
  这个结论**不延伸到重新训练**：同一个奖励改动如果进入训练目标，会改变价值网络学到的东西，进而改变排序。要否定"用它重新训练"的版本，需要另外的证据。
- **不恒为零但量级远小于现有间距** → 通道存在但窄；估算它能翻转多少比例的决策，进入查表。
- **不恒为零且量级可比** → 通道成立，进入查表。

## 例子
- 条件化进度奖励：在安全候选内两种方案的差是 `(1−b)/2`，与动作无关 → 在固定价值网络下不改变即时排序，作为部署期改动无需实验即可淘汰；它作为训练奖励会如何改变价值网络，这条推导不回答。
- 把网络输入里某个量替换成固定值：**输入上的扰动对所有候选相同，不等于分数上的变化对所有候选相同。** 网络是非线性的，同一个输入扰动经过不同候选的后继状态会产生不同的分数变化。这种改动不能用代数判定，必须实测（见下一节）。
- 并列惩罚常数（如给某个下标减 1e-3）：量级超过打分间距中位数时，它实际参与了大量决策，应当作为公式的一项列出来。
- 奖励项在存活候选间恒为零：决策完全由价值项的次序决定，此时只在部署期改奖励系数的方案没有通道——但要核实"恒为零"是否有例外状态（例如过滤全部失效的状态），并且这不适用于改了奖励再重新训练的方案。

## 常见误判
- 把"输入扰动相同"当成"分数变化相同"，对经过网络的改动做代数淘汰。
- 只看训练期公式，忽略部署期多出来的过滤和惩罚。
- 用"改动率"证明通道有效。改动率只说明排序变了，不说明变好了。
- 把对标量输入的缩放当成"调节不确定性"之类的语义操作，没验证它在参数空间实际往哪个方向移动。
