# 反事实表格式

`regret_ruler.py` 读 JSONL 或 JSONL.GZ，每行一个决策状态。字段名可用命令行参数改。

| 字段 | 默认名 | 必需 | 含义 |
|---|---|---|---|
| 候选打分 | `final_scores` | 是 | 部署策略实际用于排序的分数，长度 = 候选数。被过滤的候选用一个极小值表示（默认低于 -1e8 视为不可行） |
| 候选真实回报 | `G_A` | 是 | 每个候选"执行这一步、之后按基线策略续行到结束"的实现回报 |
| 实际选中 | `chosen` | 否 | 缺省取可行候选里打分最大者 |
| 分组 | 由 `--group` 指定 | 否 | 例如场景编号；可用 `--group-map` 合并 |
| 聚类 | 由 `--cluster` 指定 | 否 | 同一 episode 取了多个状态时填 episode 标识，bootstrap 按它重采样 |
| 主键 | 由 `--key` 指定 | compare 必需 | 用于把新打分对到同一状态 |

规则函数（rule 模式）还能读到记录里的任何其他字段（净距、候选命令、上一步动作等），所以造表时把可能用到的量一并存下。

## 造表时的要求
- 每个状态存**全部**候选的回报。只采样一部分候选时，"最优回报"被低估，regret 被低估，消除率被高估，和全量口径不可比。要省时间就减状态数，不减候选数。
- 状态抽样规则预先写死，不按结局或网络表现挑。
- 记录回报依赖的续行策略是哪份权重。换了权重，表要重造。
- 先验证无干预重放与原始轨迹逐位一致，再信任反事实分支。
- 状态按完整 episode 划分训练/开发/测试，不按状态随机划分。

## 可行集合的边界情况
- 只有一个可行候选的状态：`target` 和 `rule` 不计入（这一步没有选择余地）；`compare` 和 `channel` 保留，因为新打分可能让别的候选变得可行。
- 新打分下没有任何可行候选：工具默认报错，不替你假设策略会选什么。用 `--empty-policy keep`（部署确实退回原动作）或 `--empty-policy skip`（排除并报告个数）明确说明。
- 原打分下没有任何可行候选：`compare`/`channel` 报错。部署里"全部被过滤时掩码不生效"的状态，造表时应把候选都标为可行。

## 这张表量的是什么
单步 regret：这一步换个选择，之后仍按基线走。它是事后量（知道了这个世界的未来），是上限而不是可达增益；它不包含多步改动的累积效果。
