# 纳入与排除标准

在检索之前定好，写进 `ledger.json` 的 `criteria`。下面是默认模板，按课题改。

## 纳入（满足任一条）
1. 同一问题、同一类输入输出接口、针对同一个困难。
2. 同一评测环境或可直接比较的环境，且有可复现信息（代码、配置、seed）。
3. 不同问题，但困难的结构相同，并且机制写得足够具体可以移植。
4. 被两篇以上已纳入论文当作基线。

## 排除
1. 只有标题或关键词相似，问题设定不同（例如同样叫"crowd"，但做的是人群计数）。
2. 机制没有具体到可以实现（只有框图和结果）。
3. 无法取得全文。
4. 与已纳入论文是同一工作的早期版本——保留最完整的一版。

## 待定（maybe）的处理
读摘要判断不了时标 maybe。筛选结束前清空 maybe：要么读到能判断，要么排除并写"未能判断，未读全文"。

## 对标对象的优先级
按下面顺序挑 1–2 篇作为主对标：
1. 有开源代码且你能跑起来
2. 评测环境与你现有资产一致
3. 论文自己列出了未解决的问题，或者后续工作指出了它的问题
4. 发表在你的目标期刊或会议同级别的地方

对标的含义是在它的协议上赢它，所以第 2 条比名气重要。
